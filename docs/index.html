A Pi-hole–style sinkhole on a tiny ESP32-S3. Blocklisted domains die with a black-hole answer; everything else is forwarded and cached — and if blocking ever fails, the network keeps resolving. Fail-open by design. Un sinkhole estilo Pi-hole en un diminuto ESP32-S3. Los dominios en lista mueren con una respuesta de agujero negro; el resto se reenvía y se cachea — y si el bloqueo falla, la red sigue resolviendo. Fail-open por diseño.

What it isQué es

A whole ad-blocker in 2 MB of firmwareUn bloqueador entero en 2 MB de firmware

Every DNS query on your LAN passes through ESPHole. It runs the full fast path — parse, block, cache — inside a single non-blocking thread, so resolution stays instant while TLS, HTTP and OTA happen off to the side. Built spec-by-spec with strict test-driven development and on-hardware verification. Cada consulta DNS de tu red pasa por ESPHole. Ejecuta la ruta rápida completa — parsear, bloquear, cachear — en un solo hilo que nunca bloquea, así la resolución es instantánea mientras el TLS, el HTTP y el OTA ocurren aparte. Construido spec a spec con TDD estricto y verificación en hardware.

ArchitectureArquitectura

The fast path never blocksLa ruta rápida nunca bloquea

Pure logic (wire parsing, matching, cache, framing) is ESP-IDF-free and unit-tested on a PC; hardware modules are thin glue. Slow work runs in dedicated tasks — the tcpip thread only ever enqueues. La lógica pura (parseo wire, coincidencia, caché, framing) no depende de ESP-IDF y se testea en PC; los módulos de hardware son pegamento fino. El trabajo lento va en tareas dedicadas — el hilo tcpip solo encola.

⚠️ The DHCP server is experimental.El servidor DHCP es experimental. Its pure logic is unit-tested and the API/UI exist, but it has not been exercised on a live network — a rogue DHCP server can hand out IPs and disrupt other devices. Validate it on an isolated LAN (with the router's own DHCP disabled) before relying on it. Su lógica pura está testeada y la API/UI existen, pero no se ha ejercitado en una red real — un DHCP no controlado puede repartir IPs y perturbar otros dispositivos. Valídalo en una LAN aislada (con el DHCP del router desactivado) antes de confiar en él.

SecuritySeguridad

Hostile input is the default assumptionLa entrada hostil es el supuesto por defecto

  • Challenge-response login.Login desafío-respuesta. The browser derives PBKDF2-HMAC-SHA256(password, salt, 30000) and answers HMAC(key, nonce) — the password never crosses the wire or gets stored in plaintext.El navegador deriva PBKDF2-HMAC-SHA256(contraseña, salt, 30000) y responde HMAC(clave, nonce) — la contraseña nunca viaja ni se guarda en claro.
  • DoT connects by IP conecta por IP. The resolver's certificate is still validated against its hostname (SNI), so encryption doesn't leak the resolver via a plaintext bootstrap lookup.El certificado del resolvedor se valida contra su hostname (SNI), así el cifrado no filtra el resolvedor por una resolución de arranque en claro.
  • HTTPS by default por defecto. OTA and blocklist downloads validate against a CA bundle; plaintext HTTP is a dev-only opt-in.Las descargas OTA y de listas validan contra un bundle de CAs; el HTTP en claro es opt-in solo de desarrollo.
  • textContent, never innerHTML, nunca innerHTML. Client-supplied strings (hostnames, IPs, lease names) are inserted as text.Las cadenas del cliente (hostnames, IPs, nombres de concesión) se insertan como texto.

Build & flashCompilar y flashear

cd firmware
idf.py set-target esp32s3
idf.py build                     # firmware + web UI (www.bin)
idf.py -p /dev/ttyACM0 flash monitor

First boot starts a captive AP (ESPHole-XXXX, key on the serial console). Join it, set your Wi-Fi at 192.168.4.1, then create your admin password on first visit. Full guide in the README (EN/ES). El primer arranque levanta un AP cautivo (ESPHole-XXXX, clave en la consola serie). Conéctate, configura tu Wi-Fi en 192.168.4.1 y crea tu contraseña de admin en la primera visita.
