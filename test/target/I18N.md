# Verificación — interfaz bilingüe (spec 009)

Contrato: `specs/009-i18n/contracts/i18n-keys.md` (IK-01..08).

Es 100% frontend: no toca firmware/DNS/API. La verificación es (a) estática/lógica
automatizada y (b) manual en el navegador.

## Automatizado (sin dispositivo)

```sh
# Completitud de traducciones (IK-01..03): toda clave usada tiene en+es no vacíos.
python3 test/target/i18n_check.py     # esperado: OK, 98/98

# Lógica de la capa i18n (defecto EN, cambio ES, {0}, fallbacks).
node test/target/i18n_logic.js        # esperado: 9 PASS / 0 FALL
```

## Manual (navegador real) — IK-04..08

Abrir `http://<IP>/` (recomendado en una ventana privada para partir de cero):

| ID | Paso | Esperado |
|----|------|----------|
| IK-04 | 1ª carga (sin idioma guardado) | interfaz en **inglés**; `<html lang>`=`en` |
| IK-05 | pulsar **ES** | todo pasa a español **al instante** (sin recargar); `<html lang>`=`es` |
| IK-06 | recargar la página | sigue en **español** (persistió en localStorage) |
| IK-05b | pulsar **EN** | vuelve a inglés al instante; se recuerda |
| IK-07 | recorrer setup/login/dashboard en cada idioma | **sin** texto del otro idioma (títulos, botones, ayudas, placeholders, cards, estados de DoT/blocklist/firmware, "Xs ago"/"hace Xs") |
| IK-08 | en la consola: `localStorage.setItem('esphole_lang','zz')` y recargar | cae a **inglés** |

Nota: marcas/ejemplos que son idénticos en ambos idiomas quedan sin traducir a
propósito (IP, MAC, SNI N, URLs de ejemplo, "SERVFAIL", "ESPHole").
